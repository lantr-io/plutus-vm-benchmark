RankingRanked on decode + eval. The same scripts for every VM.

This benchmark compares the speed of Plutus virtual machines (UPLC evaluators), the programs that run Cardano smart contracts. Each VM decodes and evaluates the same 89 Plutus scripts. A correctness gate checks every result and its execution units (ExUnits) against plutus-core, the Haskell CEK machine of the Cardano node. This run of 2026-10-26 has 9 evaluators, written in Scala, Go, Rust, Haskell, Scala.js and TypeScript. The method and the source are open.

These VMs are run, gated and shown with their numbers. They are not ranked. They are not a competitor in the penalty rule and never the 1.00× reference. The ranking hatches them and gives them no rank. The history chart draws them dashed. The per-script table never marks them as the fastest. Execution modelWhy the ranking has categories.

VMs run UPLC in different ways. A UPLC-level JIT compiler does different work from a CEK interpreter, even when both run on a JIT-compiled host such as the JVM or V8. Numbers in one category compare like for like. Numbers across categories do not compare directly.

Method

Each script has two timings. Eval only evaluates a program that was decoded once, before timing. Decode + eval decodes the flat script and evaluates it in every iteration, as a node does with a script it has not seen. The ranking uses decode + eval. Decoding is a large share of the time for some VMs (about 66 % for Haskell plutus-core), so eval only shows how fast the evaluator alone is.

Correctness gate: each VM evaluates every script once more and reports the result and the ExUnits. They must equal Haskell plutus-core. A VM that differs is not ranked (“failed check”). A VM whose API cannot take the mainnet cost model is ranked with an “outdated cost model” badge, if it equals Haskell with the model the VM ships.

A VM that compiles a script before it runs it (“decode and compile excluded”) decodes and compiles each script once, before timing. Its timed loop runs the compiled script, so neither step is in its time. It has only an eval-only time and is not ranked. Its compile time is shown separately. A VM whose library caches decoded programs (“decode cached (by the library)”) decodes a script only on the first call, in the warm-up. Its timed loop runs the cache lookup and the evaluation, so its two columns have the same numbers.

Flat decode and evaluation on Plutus scripts. Each VM uses its native benchmark framework and runs in its own Docker image. Geometric means in a category use only the scripts where every VM in that category succeeded, so all VMs in a category are compared on the same scripts.

FAQPlutus VMs and this benchmark.

What is a Plutus VM?

A Plutus VM, or UPLC evaluator, runs Untyped Plutus Core (UPLC), the language of Cardano smart contracts. The Cardano node uses the CEK machine of plutus-core (Haskell) to validate scripts. Wallets, SDKs, emulators and other tools use their own evaluators to compute the script result and its execution units (ExUnits) before they submit a transaction.

What does this benchmark measure?

Each VM flat-decodes and evaluates 89 Plutus scripts from the plutus-use-cases test suite (auction, escrow, uniswap, stablecoin and others). The page shows the mean time per script and the geometric mean over all scripts. Each VM runs in its own Docker image on the same server type, one VM at a time. A VM is ranked only if its results and ExUnits equal Haskell plutus-core on every script.

Which Plutus VM is the fastest?

In the run of 2026-10-26, Scalus CEK (Scala / JVM) has the lowest decode + eval geometric mean of the ranked VMs: 207.72 µs. plutus-core, the Haskell CEK machine of the Cardano node, takes 629.02 µs (3.03× the fastest time). The VMs use different execution models (CEK interpreter, AST walker, JIT compiler), so compare VMs of the same model too. Experimental VMs are not ranked.

Why does the ranking include the decode time?

A node decodes a script from its flat encoding before it evaluates it. For a script that the node has not seen, both steps take time. For some VMs the decode is a large share of the time (about 66 % for Haskell plutus-core), so the page also shows an eval-only time.

How often is the benchmark updated?

A GitHub Actions workflow runs the full benchmark on the 1st of each month, and the maintainers start extra runs when a VM release changes. The workflow skips a scheduled run when nothing changed. This page shows the run of 2026-10-26.

How can a VM join the benchmark?

A ranked VM has a published release, a downstream user today, and passes the correctness gate. Open a pull request that adds a Docker image for the VM. Follow CONTRIBUTING.md and the image contract.
