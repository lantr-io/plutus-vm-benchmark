These VMs are run, gated and shown with their numbers. They are not ranked. They are not a competitor in the penalty rule and never the 1.00× reference. The ranking hatches them and gives them no rank. The history chart draws them dashed. The per-script table never marks them as the fastest. Execution modelWhy the ranking has categories.

VMs run UPLC in different ways. A UPLC-level JIT compiler does different work from a CEK interpreter, even when both run on a JIT-compiled host such as the JVM or V8. Numbers in one category compare like for like. Numbers across categories do not compare directly.

Method

Each script has two timings. Eval only evaluates a program that was decoded once, before timing. Decode + eval decodes the flat script and evaluates it in every iteration, as a node does with a script it has not seen. The ranking uses decode + eval. Decoding is a large share of the time for some VMs (about 66 % for Haskell plutus-core), so eval only shows how fast the evaluator alone is.

Correctness gate: each VM evaluates every script once more and reports the result and the ExUnits. They must equal Haskell plutus-core. A VM that differs is not ranked (“failed check”). A VM whose API cannot take the mainnet cost model is ranked with an “outdated cost model” badge, if it equals Haskell with the model the VM ships.

A VM that compiles a script before it runs it (“decode and compile excluded”) decodes and compiles each script once, before timing. Its timed loop runs the compiled script, so neither step is in its time. It has only an eval-only time and is not ranked. Its compile time is shown separately. A VM whose library caches decoded programs (“decode cached (by the library)”) decodes a script only on the first call, in the warm-up. Its timed loop runs the cache lookup and the evaluation, so its two columns have the same numbers.

Flat decode and evaluation on Plutus scripts. Each VM uses its native benchmark framework and runs in its own Docker image. Geometric means in a category use only the scripts where every VM in that category succeeded, so all VMs in a category are compared on the same scripts.
